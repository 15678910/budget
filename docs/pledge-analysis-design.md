# 선거 공약 과학적 분석 시스템 — 설계 문서

> 마을살림/나라살림 확장 모듈. 선거 후보 공약을 **비용추계·효율성·효용성** 관점에서
> 객관·중립적으로 분석하는 Palantir식 온톨로지 기반 시스템.
> 작성: 2026-06 / 상태: 설계(A) 완료, 데이터조사(C) 완료, MVP(B) 대기

---

## 1. 목적 & 원칙

### 목적
- 선거 공약을 **데이터로** 비교 가능하게: "얼마 드는가(비용), 얼마나 효율적인가, 누구에게 효용이 있는가"
- 유권자·의원·시민이 공약을 **과학적으로** 검증하는 도구

### 핵심 원칙 (위반 시 프로젝트 신뢰·법적 리스크)
1. **정치적 중립** — 특정 진영·후보만 분석 금지. **전 후보·전 정당 동일 기준·동일 방법론.**
2. **비용은 추계, 효용은 가정 명시** — 효용을 단정하지 않음. 모든 가정을 투명 공개.
3. **출처·방법론 공개** — 모든 수치에 산출근거·벤치마크·출처 표기 (기존 시뮬레이터 규칙 계승).
4. **공직선거법 준수** — 선거 영향·편향 목적 배제. "객관적 비용·효율 정보 제공" 성격 명확화.

### 중요 제약
- **공약서 제출 의무 직급** = 대통령·**시도지사·구시군의장·교육감**. → **광역·기초의원은 공약서 API 미제공**(선거공보 비정형만). 의원 분석은 후순위·제한적.
- **데이터 신선도**: 테스트 시점(2026-06) 일부 엔드포인트가 과거 선거만 반환 → **MVP 착수 시 2026 제9회 지방선거 sgId 재확인 필수**.
- 공약 텍스트는 **추상적** → 비용추계 위해 구체화(대상·규모 가정) 단계 필요.

## 3. 온톨로지 (Palantir식 객체-관계 모델)

```
[선거]  sgId, 선거명, 투표일, 직급종류
   │ 1:N
[후보]  cnddtId, 성명, 정당, 기호, 지역, 직급      ←── 후보자정보 API
   │ 1:N (발표)
[공약]  공약ID, 제목, 분야, 원문, 이행방법, 재원조달  ←── 선거공약 API
   │ 분류 1:1
[정책카테고리] (12종: hospital/education/welfare/...)  ←── 기존 분류기
   │ 추계
[분석]
   ├─ 비용추계   : 초기비용, 운영비, 5년총비용, 재원   ←── calculateCompoundCost
   ├─ 효율지표   : 수혜인원, 1인당비용, 재정지속성, 중복도
   └─ 효용추정   : 기대효과(가정 명시), 근거 벤치마크
```

- 객체별 **속성(properties)** + **관계(links)** → 그래프 탐색 + 비교 대시보드 (Palantir Foundry/AIP 스타일)
- 공약(Object)은 비교·필터·집계의 기본 단위

## 4. 비용추계 방법 (기존 엔진 재사용)

- `src/lib/simulation/` + `src/lib/data/standard-costs.ts`의 **NABO 표준단가 + `calculateCompoundCost`**(시너지 할인 15%)를 공약 비용추계 백엔드로 재사용.
- 절차: 공약 텍스트 → 정책카테고리 분류(12종) → 대상·규모 추정(가정) → 표준단가 적용 → 초기/운영/5년 비용.
- **모든 추계에 `methodology`·`benchmarks` 필드 필수**(기존 규칙).
- 검증: 산출액이 NABO 표준단가 범위 내인지 자동 검증(기존 검증 규칙 계승).

## 5. 효율성·효용성 지표

### 효율성 (반객관 — 산출 가능)
- **수혜인원당 비용** = 5년총비용 ÷ 추정수혜인원
- **재정지속성** = 연운영비 ÷ 해당 지자체 가용재정(기존 재정데이터 활용)
- **공약 간 중복도** = 유사 카테고리 공약 합산 시 재원 충돌
- **실현가능성** = 임기 내 집행 가능성(정성→점수화, 가정 명시)

### 효용성 (추정 — 주의)
- 단정 금지. **기대효과 + 가정 + 유사정책 벤치마크**로 제시.
- 예: "1인당 교육비 X원 증가 → (가정: 유사 투자 시 성취도 Y 변화 사례)" — 인과 단정 아님.
- UI에 "추정치·가정 기반" 명시 배지.

## 6. 정치적 중립성 가이드라인 (필수 준수)

- ✅ **전 후보 수집·분석** — 특정 후보/정당만 등재 금지.
- ✅ **동일 방법론·동일 표준단가** — 후보별 임의 가정 금지(가정은 공통 규칙).
- ✅ **순위·우열 표현 자제** — "비용 X원", "수혜 Y명" 등 **사실만**. "누가 낫다" 단정 금지 → 데이터로 사용자가 판단.
- ✅ **출처·방법론 전면 공개** + 후보 측 반론/정정 창구.
- ✅ 선거기간 운영 시 **선관위 가이드라인·공직선거법 사전 검토**(법률 자문 별도).
- ❌ 편향 색상/문구/배치, 특정 후보 강조 금지.

## 8. 기술 아키텍처

- **수집**: `scripts/fetch-pledges.mjs` — 선관위 공약/후보자 API → 정규화 JSON (`public/data/pledges-{sgId}.json`)
- **분류·추계**: `src/lib/pledge/` — 카테고리 분류기 + 비용추계(기존 엔진 래핑) + 효율지표 계산
- **API**: `/api/pledge/*` — 필요 시 런타임 조회(선관위 키 서버 전용)
- **UI**: `/pledges` — Palantir식 온톨로지 그래프 + 후보 비교 대시보드 + 공약 상세(비용·효율·효용·출처)
- **중립성**: 데이터/표현 규칙을 코드 레벨로 강제(공통 가정·동일 렌더)
