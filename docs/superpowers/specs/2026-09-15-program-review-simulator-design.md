# 사업 검토 시뮬레이터 설계

- 작성 2026-09-15
- 상태: 사용자 구두 승인 (설계 절 6개) → 본 문서로 정리
- 관련: `docs/superpowers/specs/*disputes*` (예산분쟁 설계), `src/lib/disputes/`, `src/components/disputes/calculators/`

## 0. 한 문장

정부가 낸 사업 하나하나를 **검증 가능한 사실(성격·규모·경로·근거)** 로 기술한 데이터 위에, 독자가 **기준의 가중치**를 정하면 우선순위와 재배분 결과가 바뀌는 결정론적 계산기. 사이트는 어떤 사업이 좋다고 말하지 않는다.

## 1. 배경과 문제

- 2027년 예산안은 미래대응기금 4대 계정에서 첫해 45.4조원을 쓴다. 홍보자료 「미래대응기금 주요사업」(7쪽)과 「100대 신규사업」이 사업 목록과 금액을 준다.
- 사용자가 원한 것은 "정부 사업의 효율 분석과 효율을 극대화하는 대안". 그러나 정부 문서에는 사업별 효과 추계가 없고(100대 신규사업 100건 중 기대효과 언급 5건, 예타 언급 0건), 효과 모형은 가정이 결과를 좌우하므로 이 사이트의 원칙("확인된 숫자만, 판단은 독자가")과 충돌한다.
- 그래서 "효율"을 **원자료에서 읽어낼 수 있는 렌즈**로 바꾼다. 효과는 추정하지 않는다. 독자가 기준을 정하고, 그 기준에서 정부안이 어떻게 보이는지, 대안을 짜면 돈이 어디로 가는지를 보여준다.

## 2. 범위와 단계

| 단계 | 대상 | 건수(예상) | 화면 |
|---|---|---|---|
| 1 | 미래대응기금 4대 계정 주요사업 + 계정별 「기타」 잔여 | 31 + 4 | `/disputes/future-fund` 「숫자로 보기」에 계산기 추가 (`CalculatorKey` 레지스트리) |
| 2 | 5대 중점투자 과제 (기금 밖 본예산 사업 포함) | ~40 | 새 페이지 `/investment`, 분야 필터, 사이드바 「예산분쟁」 그룹 옆 항목 |
| 3 | 100대 신규사업 전부 | 100 | 같은 페이지에 목록·검색. `scripts/parse-100-programs.mjs`로 반자동 입력 후 사람이 검수 |
| 4 | 광역단체 17곳의 주요사업 (시도 본청 예산) | 시도당 20~40 | `/investment?gov=11` — 정부 단위 선택기에서 시도 선택 |
| 5 | 자치구·시군 주요사업 | 지자체당 10~30, 단계적 | 같은 화면, 시도 → 시군구 2단 선택 |

이 문서는 **1단계**를 구현 가능한 수준으로 정의하고, 2~5단계는 데이터 모델이 그대로 수용하는지만 확인한다. 1단계를 배포해 반응을 본 뒤 다음 단계로 간다.

### 정부 단위 (사용자 요구 2026-09-15: 중앙정부·광역단체별·자치구별로도 기능할 것)

- 사업마다 `gov: { level: 'central' | 'metro' | 'district'; code: string; name: string }`를 가진다. 코드는 행정표준코드 — 중앙 `'00'`, 시도 2자리(`'11'` 서울), 시군구 5자리(`'11110'` 종로구). 사이트가 이미 쓰는 `SCHOOLINFO_REGIONS`(`src/lib/data/schoolinfo-regions.ts`)의 코드 체계와 같다.
- **점수·재배분은 항상 하나의 정부 단위 안에서만** 계산한다. 서울시 사업과 중앙정부 사업을 한 순위표에 섞지 않는다 — 재원도 심의 기구도 다르기 때문이다. 재배분 불변식의 총액은 선택한 단위의 사업 합계다.
- 렌즈 `route`(심의 경로)는 단위마다 뜻이 다르다: 중앙 = 본예산/기금, 광역·기초 = 일반회계/특별회계·기금. 값의 집합은 `ReviewRoute`에 `'special-account'`를 더해 공용으로 쓰고, 화면 라벨만 단위별로 바꾼다.
- 1단계는 `level: 'central'` 행만 있다. 화면의 정부 단위 선택기는 2단계 `/investment`에서 넣고, 1단계 계산기(분쟁 페이지 안)는 중앙 고정이다.
- **지방 사업 데이터의 출처**: 지방재정365(lofin.mois.go.kr)의 「세출예산 사업별 현황」은 API가 LINK 유형이라 프로그램 호출이 안 된다(`fiscal-health-data.ts` 주석 참조). 따라서 4·5단계는 ① 지방재정365 화면에서 시도별 CSV를 내려받아 `data/local-programs/<code>.csv`에 두고 ② `scripts/import-local-programs.mjs`로 `Program[]`으로 변환하며 ③ 분류 근거(`evidence`)는 각 지자체 「주요사업 설명서」 또는 「성과계획서」 문장을 인용한다. 자동 변환된 행도 사람이 `evidence`를 채운 뒤에만 화면에 나온다. 17개 시도를 한 번에 하지 않고, 사용자가 지정한 시도부터 한다.
- 총액 검증은 단위별로 한다: 중앙 = 45.4조(1단계), 시도 = 해당 시도 본예산 세출 총액 또는 주요사업 합계 중 문서가 주는 값.

## 3. 데이터 모델

`src/lib/programs/types.ts`

```ts
export type ProgramArea =
  | 'mega-ai' | 'growth-engine' | 'youth' | 'k-shape' | 'safety';   // 5대 중점투자
export type FundAccount = 'youth' | 'growth' | 'regional' | 'education' | 'none';
export type ProgramNature = 'new' | 'expanded' | 'transferred' | 'tax-converted' | 'unknown';
//  new 신규 / expanded 확대 / transferred 기존 급여·사업의 재원 이관 / tax-converted 조세지출→재정 전환
export type SpendType =
  | 'cash' | 'matched-saving' | 'grant' | 'equity' | 'rnd' | 'infra' | 'service' | 'unknown';
//  cash 1회성·정기 현금 / matched-saving 기여금(자산형성) / grant 보조 / equity 출자 / rnd / infra 건설·설비 / service 인력·프로그램
export type ReviewRoute = 'budget' | 'fund' | 'special-account' | 'unknown';
//  중앙: budget 본예산 / fund 기금(30% 특례 대상). 지방: budget 일반회계 / special-account 특별회계 / fund 기금

export type GovLevel = 'central' | 'metro' | 'district';
export interface GovUnit { level: GovLevel; code: string; name: string }   // 행정표준코드, 중앙은 '00'

export interface Program {
  id: string;                       // kebab-case, 예: 'youth-future-savings'
  name: string;
  gov: GovUnit;                     // 어느 정부의 사업인가. 점수·재배분은 같은 gov 안에서만
  ministry: string;                 // 중앙: 부처, 지방: 실·국
  area: ProgramArea;
  account: FundAccount;
  amount26Eok: number | null;       // 억원. 신규면 null
  amount27Eok: number;              // 억원
  nature: ProgramNature;
  spendType: SpendType;
  route: ReviewRoute;
  unit?: { price: string; count: string; product: number; matches: boolean; note?: string };
  //  단가×수량이 문서에 있는 경우. product는 억원, matches는 amount27Eok와의 일치 여부(±1%)
  beneficiaries?: { value: number; unit: string; source: string };   // 수혜 범위
  evidence: { field: keyof Program | 'unit' | 'beneficiaries'; quote: string; source: string }[];
  //  분류 근거 문장. spendType·nature·route는 반드시 근거가 있어야 한다
  sources: string[];                // 예: '기획예산처 2027년 예산안 홍보자료 7쪽'
  isRemainder?: boolean;            // 계정 「기타」 잔여 행
}
```

- 지출 유형 분류 규칙 (판단이 갈리는 곳을 미리 정한다): 개인에게 현금·바우처·장학금·지원금으로 지급 = `cash` / 개인 납입에 정부가 기여금을 얹는 적금·계좌 = `matched-saving` / 기관·지자체·기업에 보조·출연 = `grant` / 지분 취득·펀드 출자 = `equity` / 연구개발(R&D 표기 또는 기술개발) = `rnd` / 건설·설비·주택 매입 = `infra` / 인력 배치·교육훈련·프로그램 운영 = `service`. 하나의 사업이 둘 이상이면 금액이 큰 쪽을 쓰고 `evidence`에 그 사실을 적는다.
- `evidence`가 없는 분류는 테스트가 거부한다. "R&D니까 rnd"는 안 되고 사업내용의 문장을 인용해야 한다.
- 효과·성과 필드는 **없다**. 추가하려면 이 문서를 먼저 고친다.
- 2단계에서 `account: 'none'`인 본예산 사업이, 3단계에서 `area`가 5대 중점 밖인 사업이 들어온다(`area`에 `'other'` 추가 예정). 그 외 스키마 변경은 없다.

## 4. 렌즈와 점수

`src/lib/programs/scoring.ts` — 순수 함수. `components`를 import하지 않는다.

### 렌즈 (사업당 0~1로 정규화, 계산식은 화면에 노출)

| 키 | 이름 | 값 | 근거 |
|---|---|---|---|
| `capital` | 자본축적성 | equity·rnd·infra·matched-saving = 1, service·grant = 0.5, cash = 0, unknown = 제외 | 정부의 NEXT 원칙 "N 자본축적"을 그대로 씀 |
| `netNew` | 순증 여부 | new·expanded = 1, tax-converted = 0.5, transferred = 0 | 이관은 새 돈이 아니다 |
| `execution` | 집행 위험 | 증가 배율 r = a27/a26. r ≤ 1.5 → 1, r ≥ 10 → 0, 사이는 log 보간. 신규는 0.5 | 전년 집행 기반이 없는 급증은 위험 |
| `route` | 국회 심의 경로 | budget = 1, fund = 0 | 기금 사업은 30% 특례·세입보전 전출 대상 |
| `reach` | 수혜 범위 | beneficiaries 있으면 log 정규화, 없으면 제외 | |
| `check` | 검산 일치 | unit.matches = 1, 불일치 = 0, unit 없음 = 제외 | |

- 렌즈 값이 `제외`인 사업은 그 렌즈의 가중치를 분모에서 뺀다(있는 렌즈만으로 평균). 렌즈가 전부 제외인 「기타」 행은 점수 없음.

### 점수와 순위

```
score(p) = Σ_k w_k · lens_k(p) / Σ_k w_k      (k는 p에 값이 있는 렌즈, w_k ∈ {0,1,2,3})
```

가중치가 전부 0이면 점수 없이 금액순으로 보여준다.

### 프리셋

| 이름 | capital | netNew | execution | route | reach | check |
|---|---|---|---|---|---|---|
| 정부 기준 (NEXT 원칙) | 3 | 1 | 2 | 0 | 1 | 1 |
| 국회 통제 우선 | 1 | 2 | 1 | 3 | 0 | 1 |
| 자산형성 우선 | 3 | 2 | 1 | 0 | 1 | 0 |

프리셋은 출발점이다. 화면은 "이 가중치는 예시이며 바꿀 수 있다"고 적는다. 「정부 기준」은 NEXT(N 자본축적·E 과감한 투자·X 탄력적 집행·T 시급성) 중 데이터로 표현되는 N·X만 반영한 것임을 각주로 밝힌다.

### 재배분

`src/lib/programs/reallocation.ts`

- 입력: 순위, 하위 N건, 삭감률 c (0~100%), 배분처 비율 {상위 사업 / 교부금 차액 보전 / 국채 상환 / 적립}
- 풀리는 금액 F = Σ_{하위 N} a27 · c. 「기타」 행과 분류 근거가 부족해 점수가 없는 행은 삭감·증액 대상에서 제외한다 — 문서가 없다는 이유로 잘려서는 안 된다.
- 상위 사업 배분은 상위 N건에 현재 금액 비례. 교부금 차액 보전은 상한 21조(정부 추산 차액)를 넘으면 잘라서 적립으로 보낸다.
- 불변식: 재배분 후 (사업 합계 + 교부금 보전 + 국채 상환 + 적립) = 45.4조. 테스트로 고정.

## 5. 화면 (1단계)

## 7. 하지 않는 것

- 효과·성과·경제적 파급 추정. 어떤 형태로도 넣지 않는다.
- 사업 평가 등급 자체 부여. 화면의 "점수"는 독자 가중치의 함수이지 사이트의 평가가 아니다.
- 100대 신규사업 자동 파싱 결과의 무검수 반영 (3단계에서도 사람이 검수한 행만 `programs` 데이터에 들어간다).
- 계산기 공용 컴포넌트 추출 리팩터링 (별도 작업).

## 8. 열린 질문 (1단계 구현 중 확인)

- 청년 계정 「기타」 잔여가 5.9조로 크다. 홍보자료 본문 Ⅳ장이나 100대 신규사업에서 청년 계정 사업이 더 확인되면 행을 늘리고 잔여를 줄인다.
- 전남·광주 통합지원금의 "사무이관 0.65조"는 `nature: 'transferred'`로 볼지(사무와 함께 재원 이관) — 100대 신규사업 해당 항목의 사업내용을 읽고 결정하고 `evidence`에 남긴다.
- `beneficiaries`는 1단계에서 확인되는 사업(혼인지원금 48만명, 청년일경험 72만명 등)에만 넣는다. 없는 사업은 `reach` 렌즈에서 제외된다.
